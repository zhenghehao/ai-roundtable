# AI圆桌

[English README](./README.md)

AI圆桌把一个普通聊天框变成你的本地 AI 团队工作台。你可以创建不同身份的 AI 角色，把它们放进群聊或私聊房间，再用 `@角色` 分配任务，让它们从选题、讨论、写作、审核、总结一路协作到最终文件交付。

它不是“一个助手回答所有问题”，而是让你组建一支可配置的 AI 小团队：主持人控场，产品经理判断需求，技术专家评估方案，创意顾问发散思路，写手产出内容，审核员检查风险，总结员收束结论，文件大师整理成可下载文件。

AI圆桌适合想把 AI 用成工作流的人，也适合不会写复杂提示词的小白用户。第一版面向本地单机使用，不需要登录，不需要数据库；模型配置、角色、房间、聊天记录和 API Key 都保存在当前设备本地。

## 可以做什么

- 创建多个 AI 角色，例如主持人、产品经理、技术专家、反对者、总结员、写手、审核员、总编、文件大师。
- 创建多个群聊房间，每个房间拥有独立的参与角色、发言顺序、讨论轮数和聊天记录。
- 创建私聊房间，和某一个 AI 角色一对一交流。
- 在聊天框里用 `@角色名` 指定任务和执行顺序。
- 让多个角色先讨论几轮，再把结果交给下一个角色继续处理。
- 上传文件，让 AI 结合附件内容进行讨论。
- 生成结构化总结。
- 通过“文件大师”把最终结果整理成 Word、Excel、Markdown、TXT、CSV、HTML 等可下载文件。
- 导出和导入聊天历史。
- 使用中文、英文、日文等多语言界面。
- 作为本地 Web 应用使用，也可以打包为 macOS / Windows 桌面软件。

示例工作流：

```text
@选题专家 @创意顾问 你们先讨论三轮，选出一个适合普通用户的 AI 产品选题。
然后 @总结员 总结最终方向。
然后 @高级写手 写一篇文章。
然后 @审核员 检查逻辑和风险。
最后 @文件大师 整理成 Word 文件。
```

## 核心功能

### 本地优先保存

AI圆桌面向个人本地使用：

- 不需要登录。
- 不需要数据库。
- 第一版不做云同步。
- 模型配置、角色、房间和聊天记录保存在本地。
- API Key 只保存在当前浏览器或桌面应用环境。

### 模型配置

用户可以新增、编辑、测试和删除模型供应商配置。

支持协议：

- OpenAI Compatible
- Anthropic Claude

内置供应商模板包括：

- OpenAI
- DeepSeek
- 通义千问 Qwen
- Kimi
- GLM 智谱
- 豆包火山方舟
- 百度千帆
- 腾讯混元
- MiniMax
- StepFun
- Gemini
- Grok xAI
- Claude

每个模型配置包含：

- 配置名称
- 协议类型
- Base URL
- API Key
- 默认模型
- 备注

角色编辑页会和模型配置关联。如果选择 DeepSeek 配置，默认模型列表会展示 DeepSeek 相关模型，避免还停留在其他供应商的旧模型名。

### 角色管理

每个 AI 角色可以设置：

- 角色名称
- 头像颜色
- 本地头像图片
- 身份设定
- 发言风格
- 默认供应商配置
- 默认模型
- 是否启用
- Markdown 身份文件

Markdown 身份文件会作为高优先级角色设定保存。角色每次发言时都会读取这份文件；如果手动身份设定或发言风格和身份文件冲突，以身份文件为准。

### 群聊房间

用户可以创建多个群聊房间。每个房间独立保存：

- 房间名称
- 参与角色
- 发言顺序
- 默认讨论轮数
- 聊天历史
- 创建和更新时间

新建群聊时，可以选择哪些角色加入，并拖动调整发言顺序。

### 私聊

除了群聊，AI圆桌也支持和单个角色私聊。

适合这些场景：

- 和产品顾问聊产品方向
- 和写作导师修改文章
- 和技术专家讨论架构
- 和投资人视角角色评估商业模式

### `@角色` 任务流

在聊天框里输入 `@角色名`，AI圆桌会按你写的顺序执行，而不是只按房间默认顺序发言。

例如：

```text
@产品经理 @创意顾问 你们先对话三轮，探讨一个适合普通用户的 AI 产品选题。
然后 @总结员 总结一个最终可落地的选题。
然后 @高级写手 写一篇文章。
然后 @审核员 进行审核。
然后 @修正员 根据审核意见修正。
最后 @文件大师 整理成 Word 文件。
```

系统会理解为：

```text
产品经理 + 创意顾问讨论 3 轮
→ 总结员总结
→ 高级写手写作
→ 审核员审核
→ 修正员修正
→ 文件大师生成文件
```

### 附件上传

聊天输入框支持上传常见文件。

支持格式包括：

- PDF
- DOCX
- XLSX
- PPTX
- TXT
- MD
- CSV
- PNG
- JPG / JPEG
- WEBP
- HTML

对于可读取文本的文件，系统会尽量提取内容并作为上下文传给模型。对于图片，如果所选模型支持多模态能力，也可以结合图片进行分析。

### 文件大师和可下载文件

AI圆桌内置“文件大师”角色，专门负责最终交付。

它可以把讨论结果整理成：

- Word 文档：`.docx`
- Excel 表格：`.xlsx`
- Markdown：`.md`
- 文本：`.txt`
- CSV：`.csv`
- HTML：`.html`

聊天界面会识别 AI 返回的文件块，并显示为可以预览和下载的文件卡片。

示例：

```text
<file name="最终文章.docx" type="docx" font="Microsoft YaHei" title-size="24" heading-size="16" body-size="11">
# 标题
## 小标题
正文内容...
</file>
```

### 历史记录和导入导出

每个房间自动保存自己的聊天历史。

支持：

- 查看房间历史
- 复制单条消息
- 删除单条消息
- 清空当前房间
- 导出 JSON
- 导出 Markdown
- 导出 TXT
- 导入 JSON 恢复聊天记录

### 多语言界面

界面支持：

- 英语
- 简体中文
- 繁体中文
- 日语
- 西班牙语
- 法语
- 德语
- 葡萄牙语
- 俄语
- 阿拉伯语
- 韩语
- 意大利语
- 荷兰语

语言设置会影响界面文字，也会影响后续 AI 发言和总结的输出语言。

## 使用场景

### 内容创作

```text
@选题专家 给我 5 个适合小红书的 AI 工具选题。
然后 @总结员 选出最有传播潜力的 1 个。
然后 @高级写手 写成一篇小红书风格文章。
然后 @审核员 检查标题、逻辑和敏感风险。
最后 @文件大师 整理成 Word 文件。
```

### 产品评审

```text
我们要不要做一个面向小白用户的 AI 群聊软件？
请从用户需求、技术成本、商业价值和风险角度讨论两轮，最后给出是否值得继续做的判断。
```

### 技术方案讨论

```text
@技术专家 @反对者 你们先讨论两轮：
第一版是否应该只用 localStorage，不做数据库？
然后 @总结员 给出最终技术建议。
```

### 报告整理

```text
请阅读我上传的文件，提炼核心观点、风险点和下一步计划。
最后 @文件大师 整理成一份 Markdown 报告。
```

## 隐私说明

- API Key 只保存在本地。
- 不需要账号系统。
- 不需要数据库。
- 应用不会主动把 API Key 打印到控制台。
- 请不要公开包含个人 API Key 的截图或配置文件。

## 本地开发

安装依赖：

```bash
npm install
```

启动本地 Web 应用：

```bash
npm run dev
```

默认开发地址通常是：

```text
http://localhost:3000
```

如果端口被占用，可以指定新端口：

```bash
npm run dev -- --port 3001
```

## 构建网页版本

```bash
npm run build
```

构建结果会输出到 `out/` 目录。

## 部署到 Vercel

Vercel 上需要以 Next.js 应用方式运行 AI圆桌，并启用 `/api/model` 接口。项目会在检测到 `VERCEL=1` 时自动关闭静态导出，让模型请求可以通过服务端接口转发。

部署后，可以在“模型配置”页面点击“测试连接”。如果看到 `/api/model` 返回 404，说明线上接口没有部署出来，请用最新代码重新部署，并确认 Vercel 使用默认构建命令：

```bash
npm run build
```

隐私提示：在 Vercel 托管版本中，API Key 仍然保存在用户浏览器 localStorage，但每次模型调用会经过 Vercel 的 `/api/model` 接口转发到模型供应商，因为很多模型供应商不允许浏览器直接跨域请求。
